1. ЧТО ЭТО ЗА ПРОЕКТ
--------------------------------------------------------------------
Веб-приложение "страница животного зоопарка". Страница конкретной особи
(енот-полоскун по кличке Тимка) открывается на поддомене сайта зоопарка:
https://raccoon.zoostav.ru

На странице есть:
  - текстовое описание особи и история появления в зоопарке;
  - фотографии, видеозаписи и наблюдение через веб-камеру вольера;
  - возможность сделать донат на корм или лечение животного;
  - дневник наблюдений (кормление, вакцинация, спаривание, потомство,
    болезни, лечение и другие записи), в который пишут работники зоопарка.

Информация и дневник доступны также через REST API, данные хранятся в базе
данных (SQL Server или SQLite, выбирается настройкой). Вход в систему и
права доступа выполнены через cookie-аутентификацию для сайта и JWT-токены
для API.

Обязательная ссылка на главную страницу зоопарка https://zoostav.ru
размещена в шапке сайта, отдельным блоком на странице животного и в подвале.

3. КАК ЗАПУСТИТЬ
--------------------------------------------------------------------
Открыть терминал (командную строку) в папке проекта, где лежит файл
ZooStav.sln, и выполнить одну из команд.

Вариант А. С SQL Server (основной режим):
    dotnet run --project src/ZooStav.Web

Строка подключения по умолчанию (файл src/ZooStav.Web/appsettings.json):
    Server=(localdb)\MSSQLLocalDB;Database=ZooStavRaccoon;
    Trusted_Connection=True;MultipleActiveResultSets=true;TrustServerCertificate=True

Вариант Б. С SQLite (если SQL Server не установлен):
    Windows (PowerShell):
        $env:Database__Provider="Sqlite"; dotnet run --project src/ZooStav.Web
    Windows (cmd):
        set Database__Provider=Sqlite && dotnet run --project src/ZooStav.Web
    Linux / macOS:
        Database__Provider=Sqlite dotnet run --project src/ZooStav.Web

Вариант В. Из Visual Studio 2022:
    открыть файл ZooStav.sln, выбрать профиль запуска
    "ZooStav.Web (SQLite — без установки SQL Server)" и нажать F5.

При первом запуске приложение само создает базу данных, применяет миграции
и добавляет демонстрационные данные: животное, фотографии, видео, записи
дневника и донаты. Отдельно ничего создавать не нужно.

5. ЛОГИНЫ И ПАРОЛИ ДЛЯ ПРОВЕРКИ
--------------------------------------------------------------------
Работник зоопарка (может вести дневник):
    логин:  keeper@zoostav.ru
    пароль: Keeper#2026

Посетитель (дневник только читает):
    логин:  visitor@zoostav.ru
    пароль: Visitor#2026

Нового посетителя можно зарегистрировать самому (ссылка "Регистрация").
Такому пользователю автоматически выдается роль Visitor. Роль работника
Staff выдает администрация зоопарка в разделе "Пользователи".

6. ЧТО ВИДИТ ПОСЕТИТЕЛЬ, А ЧТО РАБОТНИК
--------------------------------------------------------------------
Без входа в систему доступны:
    - описание животного, его история, ареал обитания и рацион;
    - фотографии и видео;
    - наблюдение через веб-камеру вольера;
    - форма доната на корм или лечение и список уже сделанных донатов.

После входа (роль Visitor):
    - все перечисленное выше;
    - просмотр дневника наблюдений.

Работник зоопарка (роль Staff) дополнительно может:
    - создавать записи в дневнике;
    - изменять и удалять записи;
    - работать с журналом действий пользователей (раздел "Журнал");
    - назначать роли пользователям (раздел "Пользователи");
    - записывать данные в дневник через REST API.

Если посетитель попробует открыть форму добавления записи, он увидит
страницу "Доступ запрещен". При попытке записать данные через API он
получит ответ 403 (нет прав), а без входа в систему - ответ 401.

7. ДНЕВНИК НАБЛЮДЕНИЙ И ФИЛЬТРЫ
--------------------------------------------------------------------
Типы записей в дневнике:
    кормление, вакцинация, спаривание, потомство, болезнь, лечение,
    измерения, перемещение, наблюдение, прочее.

Страница дневника: http://localhost:5045/diary

Фильтры (одинаковые на странице и в API):
    тип записи         - например, Вакцинация
    дата с ... по ...  - период, формат 2026-01-01
    автор записи       - логин или ФИО сотрудника
    поиск по тексту    - слово из заголовка или описания, например "отит"
    сортировка         - по дате (новые или старые сверху), по типу, по автору
    размер страницы    - 5, 10, 20 или 50 записей

Примеры адресов для проверки фильтров:
    http://localhost:5045/diary?type=Vaccination
    http://localhost:5045/diary?dateFrom=2026-01-01&dateTo=2026-12-31
    http://localhost:5045/diary?user=keeper@zoostav.ru
    http://localhost:5045/diary?search=отит
    http://localhost:5045/diary?sort=date_asc&pageSize=50

Живые обновления: если запись добавили в другом окне (или через API), она
сразу появляется на открытой странице животного без перезагрузки.

8. REST API (КРАТКО)
--------------------------------------------------------------------
Полное описание: файл docs/API.md и страница http://localhost:5045/swagger

Адрес API локально: http://localhost:5045, на реальном сайте:
https://raccoon.zoostav.ru

Аутентификация API: JWT-токен. Токен выдается методом POST /api/auth/login,
далее передается в заголовке: Authorization: Bearer <токен>

Доступные методы:

    POST   /api/auth/register              регистрация посетителя
    POST   /api/auth/login                 вход, получение токена
    POST   /api/auth/refresh               обновление токена
    GET    /api/auth/me                    данные текущего пользователя

    GET    /api/animals                    список животных
    GET    /api/animals/{slug}             карточка животного (описание, история,
                                           фото, видео, веб-камера, донаты)
    GET    /api/animals/{slug}/media        медиатека (фото и видео)
    GET    /api/animals/{slug}/diary        дневник животного с фильтрами

    GET    /api/diary                      все записи дневника (только Staff)
    GET    /api/diary/{id}                 запись по номеру (только Staff)
    PUT    /api/diary/{id}                 изменить запись (только Staff)
    DELETE /api/diary/{id}                 удалить запись (только Staff)
    POST   /api/animals/{slug}/diary        добавить запись (только Staff)
    GET    /api/diary/types                справочник типов записей

    POST   /api/donations                  сделать донат (можно без входа)
    GET    /api/donations/{slug}            донаты животного
    GET    /api/donations/{slug}/summary    сводка по назначениям

Пример: получить токен и добавить запись в дневник (Linux/macOS)
    TOKEN=$(curl -s -X POST http://localhost:5045/api/auth/login \
      -H "Content-Type: application/json" \
      -d '{"email":"keeper@zoostav.ru","password":"Keeper#2026"}' \
      | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['accessToken'])")

    curl -X POST http://localhost:5045/api/animals/raccoon/diary \
      -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
      -d '{"type":"Feeding","title":"Вечернее кормление","description":"120 г рыбы"}'

9. КАК УСТРОЕН ПОДДОМЕН ЖИВОТНОГО
--------------------------------------------------------------------
Схема адресов:

    https://zoostav.ru                    главная страница зоопарка
    https://raccoon.zoostav.ru            страница животного (цель задания)
    https://raccoon.zoostav.ru/diary      дневник этого животного
    https://zoostav.ru/raccoon            перенаправление (301) на поддомен
    https://www.zoostav.ru                служебные поддомены, работают как обычно

Как это сделано в программе:
    1) файл ZooSubdomain.cs определяет животное по имени поддомена
       (raccoon.zoostav.ru превращается в "raccoon"), служебные поддомены
       www, api, admin игнорируются;
    2) middleware UseSubdomainRouting переписывает путь "/" на "/animal/raccoon",
       адрес в браузере при этом не меняется;
    3) контроллер AnimalController отдает страницу животного; если запрос
       пришел на основной домен, выполняется перенаправление на поддомен;
    4) имя домена задается в настройке Zoo:RootDomain в файле
       src/ZooStav.Web/appsettings.json - код при смене домена менять не нужно.

Настройка на реальном сервере (DNS, nginx, IIS) описана в файле docs/DEPLOY.md.

12. КАК ПРОВЕРИТЬ РАБОТУ (ПО ШАГАМ)
--------------------------------------------------------------------
1) Запустить проект (раздел 3).
2) Открыть http://raccoon.localhost:5045/ - это страница животного на
   поддомене. Проверить описание, историю, фото, видео, веб-камеру и
   ссылку на https://zoostav.ru.
3) Нажать "Сделать донат", заполнить форму (например, 500 рублей, корм) -
   появится страница благодарности с номером операции.
4) Открыть http://localhost:5045/diary - система попросит войти.
5) Войти как keeper@zoostav.ru / Keeper#2026 - откроется дневник,
   доступны кнопки "Новая запись", "Изменить", "Удалить".
6) Добавить запись (например, тип "Наблюдение") - она появится в списке,
   а в разделе "Журнал" появится запись о действии пользователя.
7) Проверить фильтры: /diary?type=Vaccination, /diary?search=отит,
   /diary?user=keeper@zoostav.ru.
8) Выйти и войти как visitor@zoostav.ru / Visitor#2026 - дневник доступен
   только для чтения, кнопки добавления нет.
9) Открыть http://localhost:5045/swagger - выполнить методы API:
   POST /api/auth/login, затем POST /api/animals/raccoon/diary с токеном.
10) Проверить перенаправление с основного домена на поддомен (команда
    в строке терминала):
        curl -I -H "Host: zoostav.ru" http://localhost:5045/raccoon
